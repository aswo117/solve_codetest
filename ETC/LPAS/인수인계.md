# 인수인계

본 문서는 LPAS AI Triage Agent 개발 환경 구축 방법, 실행 모드별 구동 법, 환경 변수 사양 및 시스템 유지보수를 위한 모듈 인계 사항을 정리합니다. 후임 개발자가 시스템을 빠르게 파악하고 개선할 수 있도록 가이드를 제공합니다.

## 1. 개발 및 실행 환경 구축

LPAS Triage Agent는 Python 3.8 이상 환경에서 동작하며, 로컬 추론을 위한 Ollama 프레임워크와 DuckDB 파일 입출력 권한이 필요합니다.

### 1.1 가상환경 구성 및 의존성 패키지 설치
아래의 명령어를 순서대로 실행하여 구동 환경을 생성합니다:
```bash
# 가상환경 생성 및 활성화
python3 -m venv venv
source venv/bin/activate

# 의존성 패키지 설치
pip install --upgrade pip
pip install -r requirements.txt
```
* **핵심 패키지 목록**: `fastapi`, `gradio`, `duckdb`, `sentence-transformers`, `numpy`, `requests`, `python-dotenv`, `elftools` (pyelftools).

### 1.2 빌드 및 통합 구동 스크립트 (`startup.sh`)
[startup.sh](file:///home/rsys_cam/vedha/triage/triage/LPAS_Triage_Agent/startup.sh) 쉘 스크립트는 가상환경 초기화 및 구동 전 헬스체크를 수행합니다:
* **의존성 자동 체크**: venv 내부에 필요한 패키지들이 누락되었는지 확인하고 필요시 복원합니다.
* **백그라운드 포트 포워딩 관리**: Gradio 및 FastAPI 포트 바인딩 헬스를 점검하고 백그라운드 프로세스로 기동을 스케줄링합니다.

## 2. 환경 변수 설정 규격 (`.env`)

LPAS Triage Agent의 모든 디스크 경로와 모델 옵션은 하드코딩되지 않고 [.env](file:///home/rsys_cam/vedha/triage/triage/LPAS_Triage_Agent/.env) 환경 변수 파일에 보관됩니다. 복제본 파일(.env)을 생성하고 보드 환경에 맞춰 값을 기재해야 합니다.

| 환경 변수명 | 권장 설정값 예시 | 기능 및 역할 |
|---|---|---|
| **`OLLAMA_BASE_URL`** | `http://localhost:11434` 또는 사내 API IP | 로컬/원격지 Ollama 서버 통신용 REST 포트 주소. |
| **`OLLAMA_MODEL`** | `gemma4:e4b` | 추론에 사용할 타겟 경량 LLM 모델 식별자. |
| **`DUCKDB_PATH`** | `./data/vectors.duckdb` | 3-Way RAG용 벡터 및 임베딩 텍스트가 저장될 DuckDB 파일 경로. |
| **`EMBEDDING_MODEL`**| `all-MiniLM-L6-v2` | RAG 인덱싱 시 문장을 밀집 벡터로 변환하는 임베딩 모델명. |
| **`LUPA_SOURCE_PATH`**| `/home/rsys_cam/vedha/lupa` | RAG 인덱싱 및 코드 브라우저 스캔 대상 LUPA OS 소스 루트 경로. |
| **`LUPA_PRODUCT_PATH`**| `.../lupa/products/washer/dqc/next_osp` | 보드 설정값(.conf) 정적 검증 시 1순위로 조회할 제품 config 경로. |
| **`LUPA_REFERENCE_PATH`**| `/home/rsys_cam/vedha/lupa` | 설정 및 소스코드 diff 비교 시 사용할 대조군 소스 경로. |
| **`ARM_TOOLCHAIN_PATH`**| `/usr/bin` (또는 비워둠) | `arm-none-eabi-nm`, `addr2line` 바이너리가 위치한 경로. |
| **`MAP_FILE_PATH`** | `/path/to/build/output.map` | 기본으로 로드할 Linker Map 파일 절대 경로 (옵션). |
| **`ELF_FILE_PATH`** | `/path/to/build/output.elf` | 기본으로 로드할 빌드 ELF 바이너리 파일 절대 경로 (옵션). |

## 3. 실행 가이드 (3가지 구동 모드)

### 3.1 CLI 분석 모드 (`cli.py`)
쉘 환경에서 특정 RAMDump 디렉토리 또는 파일을 바로 진단하고 파일로 내보낼 때 사용합니다:
```bash
# RAG 컨텍스트를 병합하여 크래시 요약 분석 수행 (saveresult.txt 저장)
python cli.py analyze ./dump_folder/ -q "Why did the HardFault occur?" --output ./result.txt

# RAG 인덱싱을 생략하고 소스코드 브라우저와 LLM 추론만으로 빠르게 분석 시 (--no-rag)
python cli.py analyze ./dump_folder/ --no-rag

# CLI 내에서 꼬리 질문(대화형) 분석 모드 진입
python cli.py interactive ./dump_folder/ --elf ./output.elf --map ./output.map
```

### 3.2 Gradio 웹 UI 대시보드 모드 (`web_interface.py`)
개발자가 브라우저를 통해 직관적으로 RAMDump 덤프를 드래그 앤 드롭하여 분석하고 지라 등록까지 원스톱으로 처리할 때 사용합니다:
```bash
# 기본 7889 포트로 Gradio 서버 기동
python web_interface.py -p 7889
```

### 3.3 FastAPI REST API 서비스 모드 (`api.py`)
사내 CI/CD 시스템(Jenkins 등) 및 자동화 스크립트와 연동할 수 있도록 REST 백엔드 웹 서버를 활성화합니다:
```bash
# 8000 포트로 FastAPI Uvicorn 인스턴스 실행
python api.py
```

## 4. 향후 로드맵 및 개선 방향 (To-Be)

1. **MCP (Model Context Protocol) Server 도입**:
   - 현재는 Gradio 및 FastAPI가 파이프라인의 입출력을 직접 통제하는 Tightly-coupled 방식입니다.
   - 향후 `Symbol Resolution`, `Code Browser 설정 대조`, `DuckDB 유사도 검색` 기능을 `@mcp.tool` 규격으로 포팅하여 MCP 서버로 빌드할 것을 제안합니다.
   - 이렇게 구성할 경우, 사내 Enterprise Gemini 또는 Claude 웹 브라우저 클라이언트가 스스로 판단하여 Jetson AGX 보드 내부의 디버그 툴을 호출하는 자율형 Agentic Workflow로 고도화할 수 있습니다.
2. **Zero-Touch Workflow 연동**:
   - 서버 파이프라인에 크래시 자동 감지 데몬을 장착하여, 빌드 검증 또는 필드 테스트 시 크래시 덤프가 수집되는 즉시 사람의 개입 없이 진단을 수행하고 JIRA WBS 티켓 발행 및 메일 전송까지 100% 자동 처리하도록 확장합니다.
